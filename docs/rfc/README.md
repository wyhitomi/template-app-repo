# Requests for Comments (RFCs)

RFCs are for proposals that deserve discussion **before** implementation:
cross-team impact, new infrastructure or vendors, public API / data model
changes, security-sensitive changes, or anything costly to reverse.

## Lifecycle

`Draft` → `In review` → `Accepted` | `Rejected` | `Withdrawn` → (`Implemented`)

1. Copy [`0000-template.md`](0000-template.md) to `NNNN-short-title.md`.
2. Open a **draft PR**; share it with stakeholders. Set a review deadline (typically 1-2 weeks).
3. Resolve comments in the doc. Decision is recorded in the RFC and, where
   relevant, as one or more [ADRs](../adr/).
4. Merge the PR with the final status, including rejected RFCs (they document what we chose not to do).
